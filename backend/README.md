# Smart Billing Application — Backend

Spring Boot REST API for a billing/invoicing system, built for the Finlec Technologies
Full Stack Developer Internship assessment.

## Tech stack

- Java 17
- Spring Boot 3.3 (Web, Data JPA, Validation)
- MySQL 8
- Lombok
- JUnit 5 + Mockito

## Features

- Customer CRUD
- Product/service catalog CRUD (with per-item tax %)
- Invoice creation with server-side calculation of subtotal, tax, discount, and total
- Invoice status workflow: `UNPAID → PAID / OVERDUE / CANCELLED`
- Dashboard endpoint: total revenue, pending amount, invoice counts by status
- AI-generated invoice summary (Google Gemini), with a safe fallback if no API key is set
- Centralized error handling (validation errors, 404s, 500s) via `@RestControllerAdvice`
- Unit tests covering the invoice calculation logic

## Getting started

### 1. Prerequisites

- Java 17+
- Maven 3.8+
- MySQL running locally (or update the connection string to point elsewhere)

### 2. Configure the database

Create a database (or let the app create it automatically — see below):

```sql
CREATE DATABASE smart_billing_db;
```

By default the app connects to:

```
jdbc:mysql://localhost:3306/smart_billing_db
```

Update `src/main/resources/application.properties` with your own MySQL username/password:

```properties
spring.datasource.username=root
spring.datasource.password=root
```

`createDatabaseIfNotExist=true` is already set in the URL, so the schema will be created
automatically on first run if it doesn't exist. Tables are auto-generated by Hibernate
(`spring.jpa.hibernate.ddl-auto=update`).

### 3. (Optional) Enable the AI summary feature

Get a free Gemini API key from [Google AI Studio](https://aistudio.google.com/apikey),
then set it as an environment variable before starting the app:

```bash
export GEMINI_API_KEY=your_key_here
```

If this isn't set, the `/api/invoices/{id}/ai-summary` endpoint still works — it just
returns a simple templated summary instead of an AI-generated one.

### 4. Run the app

```bash
mvn spring-boot:run
```

The API will be available at `http://localhost:8080`.

### 5. Run tests

```bash
mvn test
```

## API overview

| Method | Endpoint                          | Description                     |
|--------|------------------------------------|----------------------------------|
| GET    | `/api/customers`                  | List customers                  |
| POST   | `/api/customers`                  | Create customer                 |
| PUT    | `/api/customers/{id}`             | Update customer                 |
| DELETE | `/api/customers/{id}`             | Delete customer                 |
| GET    | `/api/products`                   | List products                   |
| POST   | `/api/products`                   | Create product                  |
| PUT    | `/api/products/{id}`              | Update product                  |
| DELETE | `/api/products/{id}`              | Delete product                  |
| GET    | `/api/invoices`                   | List invoices                   |
| GET    | `/api/invoices/{id}`              | Get invoice detail               |
| POST   | `/api/invoices`                   | Create invoice (calculates totals) |
| PATCH  | `/api/invoices/{id}/status`       | Update invoice status            |
| DELETE | `/api/invoices/{id}`              | Delete invoice                  |
| GET    | `/api/invoices/dashboard`         | Summary stats                   |
| GET    | `/api/invoices/{id}/ai-summary`   | AI-generated customer note       |

### Example: create an invoice

```json
POST /api/invoices
{
  "customerId": 1,
  "items": [
    { "productId": 1, "quantity": 2 },
    { "productId": 3, "quantity": 1 }
  ],
  "discountPercent": 10,
  "dueDate": "2026-08-15",
  "notes": "Thanks for your business!"
}
```

The backend computes `subtotal`, `taxAmount`, `discountAmount`, and `totalAmount` —
the client never sends these values directly, which keeps the billing math trustworthy.
